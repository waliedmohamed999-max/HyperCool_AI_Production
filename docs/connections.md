# إعداد مرحلة الذكاء الاصطناعي والكتالوج

1. انسخ `.env.example` إلى `.env` في جذر المشروع محليًا.
2. ضع `ANTHROPIC_API_KEY` و`ANTHROPIC_MODEL` (معرف موديل متاح لحسابك) و`SALLA_ACCESS_TOKEN`.
3. أعد تشغيل `npm start`. القيم تُقرأ على الخادم فقط؛ الواجهة تعرض حالة وجود الإعداد ولا تعرض المفاتيح.
4. سجل الدخول كمالك واضغط «تحديث من سلة». يحتاج رمز سلة صلاحية قراءة المنتجات `products.read`. هذا الإصدار يقبل access token موجودًا؛ تجديد OAuth وتلقي webhooks لم يُنفذا بعد.
5. اعتمد نبرة العلامة في الذاكرة، ثم أضف مواصفة معتمدة لكل منتج مطلوب باستخدام معرفه المعروض في الكتالوج ومصدرها. تسجيل المصدر إقرار بشري ولا يعني أن التطبيق فحص الرابط أو المستند.
6. اختر المنتج والمنصة والتاريخ في مساعد الكتابة، واضغط «توليد مسودة للمراجعة». هذا يستدعي API وقد يستهلك رصيد حساب Anthropic.

## ما يُرسل للموديل

الفكرة والمنصة والتاريخ، اسم المنتج ورابطه، نبرة العلامة ومواصفات المنتج المعتمدة ومصادرها وإصداراتها. لا تُرسل بيانات العملاء أو بيانات الدخول. لا تُمرر الأسعار والمخزون والادعاءات الطبية في هذا المسار. لا تضف أسرارًا أو بيانات عملاء إلى ذاكرة العلامة.

## الحدود الحالية

- وكيلا الكتابة والامتثال فقط متصلان بمسار تشغيل فعلي؛ بقية الوكلاء تعريفات جاهزة للمراحل التالية.
- فحص الامتثال الآلي استشاري بحت: يعمل على مسودة بحالة DRAFT فقط، يقرأ approved_claim وproduct_fact وpolicy المعتمدة من الذاكرة، ولا يقرأ الأسعار أو المخزون. تصنيف BLOCK من الموديل يجب أن يرافقه status=BLOCKED في الغلاف وإلا يُرفض الناتج بالكامل (فشل مغلق). لا يُنشئ الفحص مراجعة موثقة ولا يغيّر حالة المحتوى؛ حقول checklist اعتماد المراجع البشري إلزامية دائمًا.
- الاتصال يستخدم Messages API والنص المطلوب كـJSON، مع تحقق محلي صارم من العقد. لا يعتمد على ضمان JSON من المزود. الرد المبتور أو غير المطابق يُرفض.
- الناتج يبقى DRAFT بمراجعة بشرية. التحقق البنيوي ومطالبات البرومبت لا يثبتان صحة كل جملة؛ لا يوجد امتثال آلي شامل أو نشر خارجي.
- حقول كتالوج سلة تحتفظ بمصدر ووقت الجلب. سعر العرض المستورد هو taxed_price عند وجوده بعملة SAR، والقيم الغائبة/غير المحددة تبقى null. المخزون غير المحدود أو المدَار بالفروع لا يحوّل إلى كمية افتراضية.
- المزامنة تقرأ حتى 20 صفحة ثم تستبدل الكتالوج وسجل المزامنة داخل معاملة واحدة؛ أي فشل قبل الاكتمال يبقي الكتالوج السابق. تُرفض روابط المنتجات خارج hyper-cool.com، حتى لو كان السبب إعداد نطاق المتجر.
- لا يُنشأ محتوى لمنتج غير معروض أو معلوم نفاده. يلزم تحديث المنتج خلال آخر 24 ساعة، ونبرة ومواصفات معتمدة غير مسحوبة أو منتهية.
- يُعاد فحص السياق بعد استجابة الموديل؛ تغيّر الإصدارات أو سحب اعتمادها يمنع حفظ المسودة.
- مفاتيح الطلب تمنع التكرار لنفس المستخدم والمدخلات، وتظل محفوظة عبر إعادة التشغيل. الطلب الجاري عند توقف الخادم يصبح INTERRUPTED ولا يُعاد تلقائيًا، لأن المزود قد يكون احتسب التكلفة.
- مهلة الاستدعاء 45 ثانية، وطلب توليد واحد متزامن لكل عملية خادم. لا توجد إعادة محاولة تلقائية للاستدعاءات المدفوعة. في حال انقطاع المتصفح يمكن إعادة إرسال نفس الطلب قبل تغيير حقوله؛ مفتاحه محفوظ في الصفحة الحالية فقط.
- الاستخدام المسجل متاح للردود التي وصلت بنجاح فقط؛ سجلات المزود مرجع الفوترة في المهلات والأخطاء.
- هذه بيئة محلية بعملية خادم واحدة، وليست خدمة عامة متعددة النسخ. `.env` ملف أسرار محلي مستبعد من Git، وليس بديلًا لخزنة أسرار عند النشر.

## المراجع الفنية

تمت مطابقة طريقة الاستدعاء والمصادقة مع [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages/create)، وبنية المنتجات والتصفح مع [Salla List Products](https://docs.salla.dev/5394168e0). الاختبارات المحلية تستخدم ردودًا محاكية ولا تثبت صلاحية حسابات حقيقية.
