# HyperCool — تدقيق الواجهة قبل إعادة التصميم

تاريخ التدقيق: 9 سبتمبر 2026. النطاق: واجهة النظام الحالية فقط، مع الحفاظ على قواعد العمل وعقود API والمصادقة.

## البنية الموجودة

- Frontend: HTML وES modules دون إطار عمل. التنقل الحالي hash routes بين عشر صفحات.
- Styling: ملف `public/style.css` واحد، قرابة 400 سطر، مع tokens جزئية ووسائط responsive متداخلة. لا Tailwind أو CSS modules.
- Typography: IBM Plex Sans Arabic محلي بأوزان 400–700، مع ملفات عربية ولاتينية؛ يُحتفظ به.
- Components: helpers عرض جزئية في `format.js`، لكن البطاقات والنماذج والجداول والتفاصيل تُنسخ كسلاسل HTML داخل الوحدات.
- Layout: sidebar ثابتة و`main` وصفحات `.page`، دون AppShell أو Topbar أو PageHeader مشتركة.
- Forms/actions: معرفات وعلامات data attributes مرتبطة بمستمعات أحداث في `app.js` ووحدات CRM والتخطيط والوكلاء. يجب الحفاظ عليها عند نقل النموذج إلى drawer.
- Dialogs: التفاصيل داخل `<details>`، وتغيير مرحلة CRM يستعمل `prompt()` الأصلي. لا dialog system.
- Breakpoints: 1100، 1000، 800، 640، بتعريفات متفرقة. الهاتف يعرض navigation أفقيًا بدل drawer.

## الدين البصري

- `.stat,.panel,form,.card` تشترك في نفس الشكل والظل؛ لا تمييز بين المقاييس والمحتوى والنماذج.
- تفاوت حشو البطاقات وتكرار widths والجداول، وعدم وجود حدود موحدة للـforms.
- sidebar بلا مجموعات أو أيقونات؛ زر خروج بارز أعلى كل صفحة.
- Overview لا يعرض البيانات التنفيذية المتاحة بالفعل في APIs.
- نماذج إنشاء الحساب والذاكرة والمسودة تعرض دائمًا، وبعض بطاقات الوكلاء تعرض ضبط صلاحية طويلًا.
- Empty states متكررة وبعضها نص مجرد؛ أحجام كبيرة ونقص في CTA.
- badges جزئية، emojis كأيقونات نظام، وتباين ضعيف بين الأزرار الأساسية والثانوية.
- جداول بلا بحث أو فرز أو pagination مشتركة. سجل العمليات والحسابات مجرد أسطر.
- لا توجد حالات تحميل وخطأ موحدة ولا توست قابل للإغلاق أو إدارة focus للحوار.
- الألوان الأساسية مركزية جزئيًا، لكن shadows/spacing والتنسيقات المتكررة تحتاج فصلًا معماريًا. لا توجد مكتبة مكونات UI منظمة.

## خطة إعادة التصميم

1. Tokens للون والخط والمسافة والحجم والحركة، وفصل CSS إلى طبقات واضحة.
2. مكتبة DOM/HTML صغيرة بلا frontend dependency: icons، badges، cards، metrics، empty/skeleton، buttons/forms، DataTable، Dialog/Drawer، Tabs، Toast.
3. AppShell مع Sidebar/Topbar/PageHeader، تنقل متجاوب، قائمة مستخدم حقيقية، بحث سريع عبر البيانات التي يملك المستخدم صلاحية قراءتها.
4. إعادة توزيع الصفحات الحالية ونقل النماذج إلى drawers مع إبقاء عقدها ومعرفاتها ومستمعاتها.
5. إعادة تصميم عرض البيانات الحقيقية للمحتوى والوكلاء والذاكرة والتكاملات والتقارير وCRM والسجل والحسابات.
6. فحص كل route في Edge/Chromium عبر Playwright على 1440 و1920 و768 و390، وفحص الوصولية والوظائف الأساسية في قاعدة مؤقتة منفصلة.
