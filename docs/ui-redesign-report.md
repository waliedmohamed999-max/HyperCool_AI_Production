# تقرير إعادة تصميم HyperCool AI Operating System

التاريخ: 9 سبتمبر 2026. النطاق: إعادة بناء طبقة العرض والتنقل والمكونات مع إبقاء المصادقة وعقود API وقواعد المراجعة والاعتماد والتشغيل الحالية.

## A. نظام التصميم

واجهة عربية RTL هادئة: شريط جانبي كحلي، أسطح بيضاء، خلفية رمادية فاتحة، ولمسات teal للإجراءات الأساسية. احتُفظ بخط IBM Plex Sans Arabic المحلي بأوزان 400–700. لم يُضف إطار عمل أو مكتبة تشغيل للواجهة؛ المكونات ES modules تعمل داخل البنية الموجودة.

بدأ العمل بتدقيق موثق في [ui-design-audit.md](ui-design-audit.md)، ثم طبقات التصميم، ثم AppShell، ثم إعادة توزيع الصفحات وربط المكونات ببياناتها الحقيقية.

## C. المكونات

`public/components/ui/index.js` يوفر مكونات DOM/HTML مشتركة:

- Button: أساسي، ثانوي، ghost، danger، وأحجام صغيرة وعادية وكبيرة؛ يدعم الأيقونة والتعطيل.
- Card / MetricCard عبر القوالب والأنماط المشتركة، مع عرض القيمة المفقودة كشرطة بدل اختلاق صفر.
- Badge وStatusIndicator، بألوان ونصوص لا تعتمد على اللون وحده.
- الحقول والنماذج: labels، حالات required، تركيز واضح، اتجاهات مناسبة، ورسائل أخطاء داخل النموذج.
- DataTable: بحث، ترتيب، pagination، عدد نتائج، رؤوس sticky، scroll قابل للتركيز. تصنيف العملية والمنفذ في السجل، والصلاحية في جدول الفريق.
- Tabs بتحديد واضح، `aria-selected`، والتحكم بالأسهم وHome/End.
- Dialog/Drawer باستخدام `<dialog>` الأصلي، مع Escape وإرجاع المحتوى الأصلي؛ النماذج تحتفظ بمعرفاتها ومستمعاتها.
- نافذة تأكيد للقرارات المؤثرة، وحوار طلب سبب نقل فرصة المبيعات.
- Dropdown للحساب، Tooltip للتنبيهات، Toast قابل للإغلاق، Skeleton، EmptyState، وأيقونات SVG محلية.

الـpagination تخص النتائج التي أعادها الخادم. لا تدعي الواجهة جلب سجل غير محدود أو إضافة pagination على الخادم.

## D. مكونات التخطيط

`public/components/layout/app-shell.js` يجمع Sidebar وTopbar وPageHeader والتنقل:

- مجموعات العمليات، وعمليات الذكاء الاصطناعي، والنظام.
- أسماء الصفحات وأيقوناتها ومؤشر الصفحة الحالية، وbreadcrumbs وعنوان المتصفح.
- الاسم والدور والأحرف الأولى من الحساب الحقيقي أسفل الشريط الجانبي.
- قائمة الحساب، الملف الشخصي، رابط إعدادات مساحة العمل، وخروج واضح غير بارز أعلى الصفحة.
- بحث Ctrl+K في الصفحات والمحتوى والذاكرة؛ بحث العملاء عبر API للحسابات المسموح لها.
- التنبيهات تُحسب من المحتوى المعلق وقرارات الوكلاء والتصعيدات الفعلية.
- قائمة هاتف مع حاجز خلفي، `inert` للمحتوى، وإدارة التركيز وEscape.

## G. الأنماط القديمة

استُبدل CSS الأحادي القديم بملف دخول صغير يستورد ست طبقات واضحة. أزيل توحيد شكل النموذج والبطاقة في قاعدة واحدة، وأزيلت قواعد التنقل الأفقي للهاتف وdark mode التلقائي غير المتسق. نقلت font-face إلى طبقة محلية مستقلة. احتفظت أصناف الرسوم والتقارير والعلامات المرتبطة بالوظائف بعقدها، وأعيد تعريف عرضها ضمن النظام الجديد.

## H. Responsive

تم فحص 1440 و1920 و768 و390px. Sidebar ثابت على الشاشات الكبيرة، وقائمة تُفتح عند الحاجة على الأجهزة الأصغر. شبكات البطاقات تنتقل من ثلاثة أعمدة إلى اثنين ثم عمود. النماذج عمود واحد على الهاتف. الجداول والتقويم ولوحة المراحل تتمرر داخل مناطقها. RTL للتخطيط والعربية، وLTR للبريد والروابط والتواريخ الرقمية والمعرفات حيث يلزم.

## I. Accessibility

Skip link، وترتيب تركيز، وأسماء للأزرار الأيقونية، وlabels، و`aria-current` للتنقل، وARIA للتبويبات، ونوافذ native modal. التصنيفات والبحث قابلة للوحة المفاتيح. الجداول تحتفظ بعناصر الصف الأصلية والإجراءات. لا تعتمد حالات النجاح والتحذير على اللون وحده، وتوجد استجابة لـ`prefers-reduced-motion`.

فحص axe على الأربعين حالة لم يرصد مخالفات WCAG 2 A/AA و2.1 AA في العناصر المرئية. هذا فحص آلي وليس شهادة مطابقة شاملة أو بديلًا لاختبار قارئ شاشة بشري.

## J. التحقق البصري

شُغلت المسارات العشرة في Edge/Chromium، والتُقطت أربعون لقطة في `artifacts/ui/after/`، بالإضافة إلى لقطة drawer الوكيل. روجعت بصريًا صور من النظرة العامة والمبيعات والتقويم والتقارير والمحتوى والوكلاء والذاكرة والتكاملات والسجل والحسابات، بما فيها صور هاتف. أُصلحت مساحات تمدد بطاقات الذاكرة، وطول أعمدة المراحل، وتكرار عناوين الصفحات، وتوزيع التقويم والموافقات.

صور `artifacts/ui/smoke/` تخص التصميم الجديد. التدقيق النصي هو المرجع المتاح للحالة السابقة؛ لا تُقدّم تلك الصور على أنها مقارنة before/after.

## K. الاختبارات والتشغيل

- `npm test`: **92 ناجحًا، صفر فشل** بعد تغييرات الواجهة.
- `npm run test:ui`: مصفوفة **10 صفحات × 4 أحجام**، وأخطاء المتصفح، والتجاوز الأفقي، وaxe.
- رحلات فعلية في قاعدة SQLite مؤقتة: إعداد حساب؛ إنشاء محتوى؛ مراجعة واعتماد مع confirmation؛ اعتماد معلومة؛ شهر/أسبوع/أجندة؛ جدولة؛ إنشاء عميل وفتح ملفه؛ إضافة مراجع؛ Ctrl+K؛ تشغيل endpoint سجل الوكيل؛ حفظ وفتح تقرير؛ pagination وبحث وترتيب؛ سجلات ذات أسماء طويلة؛ فتح/إغلاق قائمة الهاتف؛ خروج ودخول بحساب مراجع والتحقق من إخفاء أفعال غير مسموحة.
- لا بيانات اختبار أضيفت لقاعدة المشروع، ولا مفاتيح مزود داخل الاختبار، ولا scheduler يعمل في قاعدة الاختبار.
- التصفح الوظيفي والصور يعملان مع CSP الإنتاجية. axe يعمل في سياق منفصل يسمح فقط بأدوات القياس الخاصة به؛ سياسة خادم المشروع لم تُرخَّص.
- أُعيد تشغيل سيرفر المشروع؛ الصفحة وملفات المكونات وCSS وSVG تستجيب HTTP 200 على `http://localhost:3000`.

## L. الدين والحدود المتبقية

الصفحات الطويلة مثل التقرير التنفيذي ما زالت تجمع الأقسام الوظيفية الكاملة؛ لم تُحذف أقسام لتقصير الصفحة. بعض وحدات العرض القديمة ما زالت تُنتج HTML قبل أن تطبق طبقة workspace المكونات الجديدة؛ فصل جلب بيانات كل صفحة إلى تحميل كسول خطوة مستقبلية للأداء، وليست مطلوبة لتشغيل التصميم.

الفحص تم على Edge/Chromium، وليس Safari/Firefox أو أجهزة لمس فعلية. الجداول تفلتر البيانات المُعادة من APIs الحالية، وقد تكون endpoints محدودة بعدد سجلات. لا توجد إحصاءات نجاح أو نشاط أو دعوات أو اتصالات موهومة لتعويض بيانات غير متاحة.

## M. المشكلات الوظيفية المكتشفة

- صيغة `pattern` القديمة لاسم الدخول لم تعد صالحة في نمط RegExp `v` بمتصفحات Chromium الحديثة؛ هُرّب رمز الشرطة دون تغيير القاعدة المقبولة.
- زر اختبار الوكيل كان يظهر للمراجع رغم رفض API لهذا الدور؛ أصبح مخفيًا له.
- عرض Frost كان يوحي بالتشغيل التلقائي حتى عندما يكون المجدول غير نشط؛ صار يعرض حالة المجدول الفعلية.
- القيم الرقمية المفقودة في helpers كانت تظهر صفرًا؛ أصبحت شرطة، مع الاحتفاظ بالصفر الحقيقي.
- ملفات CSS/JS الجديدة تطلبت إضافة صريحة إلى allowlist الخادم، مع بقاء CSP وقيود المسارات.
- الخدمات التي لا تملك تكامل نشر فعلي أو إدارة حساب أو دعوات أو ملفات PDF مستقلة تظل بحدودها الحالية، وتعرض الواجهة ما هو متاح فقط.
