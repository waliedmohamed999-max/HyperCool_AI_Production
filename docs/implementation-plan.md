# نطاق التنفيذ والقرارات

## المرجعية

ملف Scope v1 يحدد النتائج ومراحل التسليم. Playbook v2 يحدد عقود الوكلاء وسلوك القرار. المعلومات الموسومة Verified في المستندات لم يعاد التحقق منها في هذا التطبيق.

## الصلاحيات

التعريف الأساسي المؤقت من Playbook v2: L0 اقتراح فقط؛ L1 تجهيز مع اعتماد قبل الإجراء الخارجي؛ L2 إجراءات منخفضة المخاطر مصرح بها؛ L3 تنفيذ موسع وفق مصفوفة صلاحيات. لا ترقية تلقائية. اعتماد تقويم أسبوعي لا يعني الإذن بإرسال محادثات. النسخة الحالية تحفظ الاعتماد فقط ولا تنفذ إجراءات خارجية.

## المرحلة المنجزة

أساس محلي لواجهة التشغيل ومسار مسودة → مراجعة موثقة → اعتماد. اكتمل في 9 سبتمبر 2026:

- استخراج البرومبتات الأصلية للـ12 وكيلًا والقواعد المشتركة ومكتبة المهام.
- غلاف قرار JSON ومخطط payload لكل وكيل، مع تحقق Ajv وقواعد رفض للقرارات المتناقضة الأساسية. التحقق البنيوي لا يثبت صحة المعلومات.
- SQLite للبيانات والحسابات والجلسات، واستيراد JSON السابق مرة واحدة دون حذف المصدر.
- إعداد أول مالك، تسجيل دخول وخروج، إضافة مستخدمين وأدوار مالك ومراجع ومشغل.
- صلاحيات على الخادم، CSRF، حد لمحاولات الدخول، تسجيل هوية صاحب المراجعة والاعتماد في سجل العمليات.
- اختبارات تكامل لمسار العمل، منع انتحال الاسم وتجاوز الصلاحيات، إبطال الجلسة، الترحيل واستمرار البيانات والتراجع عن المعاملة الفاشلة.

بطاقات الوكلاء تعريفات جاهزة للربط وليست وكلاء AI عاملين. التخزين الحالي يحتفظ ببيانات التشغيل كوثيقة JSON داخل SQLite، بينما الحسابات والجلسات جداول منفصلة؛ فصل جداول CRM والذاكرة والمحتوى يكون عند إضافة تلك الوحدات.

## المراحل التالية

1. **منجز محليًا:** استخراج برومبتات v2 إلى تعريفات مستقلة وعقود JSON متحقق منها؛ إضافة قاعدة بيانات ومصادقة وأدوار المالك والمراجع والمشغل.
2. **منجز برمجيًا ومختبر بمحاكاة؛ ينتظر الحسابات:** استدعاء Anthropic للكتابة من الخادم وقراءة مفاتيحه من البيئة؛ ذاكرة بإصدارات ومصادر واعتماد المالك؛ استيراد سلة للأسعار والمخزون مع زمن ومصدر لكل حقل. واجهة التوليد تحفظ مسودات فقط مع منع التكرار وتسجيل التشغيل. إعداد OAuth والتجديد التلقائي وخزنة أسرار الإنتاج ما زال مطلوبًا قبل الإطلاق؛ راجع `connections.md`.
3. **منجز جزئيًا:** تقويم قواعد ثابتة، كتابة AI من المرحلة السابقة، فحص امتثال آلي مساعد (Anthropic) على المسودة قبل تسجيل المراجعة — يعرض تصنيف وملاحظات لكل حقل غير مطابق للذاكرة المعتمدة، مقيد بحالة DRAFT، محسوب على بصمة النسخة، ولا يغيّر حالة المحتوى أو يعتمد بديلًا عن تأكيد المراجع اليدوي، ثم مراجعة بشرية للأصل والنص، اعتماد مرتبط بالبصمة، تعديل ورفض مع إلغاء الجدولة، ملف n8n غير مفعّل للحزمة اليومية وتجهيز المستحق. الاستراتيجية والتصميم لم تُربطا بعد؛ لا توجد تسوية نشر بعد المهلات قبل بناء موصل نشر حقيقي.
4. **التقويم والحزمة والجدولة منجزة محليًا؛ النشر ينتظر الربط:** تقويم 30 يومًا وحزمة محلية يومية، وخانات LinkedIn الأحد والثلاثاء والخميس، وجدولة تمنع التكرار وتعيد التحقق من الاعتماد. ملف n8n يحدد الساعة 08:00 بتوقيت الرياض، لكنه لم يُشغّل داخل n8n هنا. راجع `planning-and-n8n.md`.
5. **منجز محليًا جزئيًا:** CRM للفرص وتأهيلها وتعيين مسؤول، تسجيل وارد يدوي بمفاتيح منع التكرار، ملخص تحويل وبيانات طلب العرض، إدخال فرص B2B بمصدر ومحفز مؤرخ، موافقات مستقلة للقنوات وopt-out، ستة أنواع مسودات متابعة AR/EN واعتماد وإيقاف حسب تغير السياق. لا يوجد استقبال أو إرسال بالقنوات أو بحث عملاء آلي أو عروض رسمية؛ قوالب WhatsApp لم تُرسل للاعتماد. راجع `crm-and-followups.md`.
6. **منجز جزئيًا:** تقرير أسبوعي (أحد–سبت بتوقيت الرياض) يجمع فقط ما سجّله النظام فعليًا — عدد المحتوى المخطط لكل منصة، فجوات التقويم، حالة الجدولة، نتائج فحص الامتثال الآلي، عملاء ومتابعات CRM الجديدة، وتغييرات صلاحية الوكلاء — بمعاينة حية وحفظ لمرة واحدة لكل أسبوع (idempotent). حقول الأداء التسويقي الحقيقية (متابعون، جلسات متجر من السوشيال، محادثات، تحويل) تبقى `null` بسبب موضح لعدم وجود اتصال بأي منصة أو تحليلات متجر بعد؛ لا تُقدَّر تخمينًا. قياس الأداء الآلي (وكيل Performance) واختبارات التشغيل ودليل المشغل ما زالت غير منجزة.
7. **منجز:** سجل استقلالية بالمالك لكل وكيل (L0–L3)، سبب إلزامي، ترقية بخطوة واحدة فقط، خفض فوري لأي مستوى كصمام أمان، وتاريخ كامل غير قابل للحذف. المستوى الآن **يُنفَّذ فعليًا** على كل استدعاء أداة عبر `src/runtime/permissions.js` (انظر بند 8) — لم يعد شارة عرض فقط. أهلية الترقية (`ELIGIBLE_FOR_PROMOTION`) تُحسب من تشغيلات حقيقية عبر `GET /api/agents/:id/health`؛ الترقية نفسها تبقى قرارًا بشريًا 100%، بلا أي أتمتة، بما يوافق مبدأ «لا ترقية تلقائية» أعلاه.
8. **منجز جزئيًا — محرك وكلاء موحد:** بُني تحت `src/runtime/` (سجل وكلاء، تنفيذ عام واحد لكل الاثني عشر، مكتبة أدوات حقيقية، إنفاذ صلاحية فعلي، أحداث، تصعيد، موافقات، مزود LLM قابل للاستبدال). سيناريو كامل مربوط وشغّال: رسالة CRM واردة ← حدث ← Frost ← تشغيل حقيقي بأدوات `get_product`/`get_current_price` ← رد داخلي، بلا إرسال خارجي. بقية الوكلاء تعمل عبر نفس المحرك وتُختبر يدويًا من زر «اختبار الوكيل» في كل بطاقة، لكن بلا منطق أعمال مكتوب خصيصًا لكل حالة عمل (اعتراض، عميل غاضب، مقارنة منافس...) — ذلك متروك للبرومبت النصي فقط ولم يُختبر بمحادثات حقيقية بمفتاح API فعلي. لا مجدول زمني (AgentScheduler) بعد؛ التفعيل حدثي أو يدوي فقط. التفاصيل الكاملة في `docs/agent-runtime.md`.

## بيانات مطلوبة للربط

- حساب Instagram الأساسي وصفحة Facebook وحالة WhatsApp Business Platform.
- حسابات API وصلاحيات المنصات وبيئة n8n؛ لا توضع الأسرار في المستندات أو المستودع.
- كتالوج وأسعار ومخزون وادعاءات معتمدة وهوية بصرية وسياسات ضمان وتوصيل وخصومات.
- اسم مسؤول الاعتماد والتصعيد وساعات العمل وCRM المختار.
