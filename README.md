# HyperCool — مركز تشغيل التسويق والمبيعات

HyperCool تطبيق ويب لإدارة المحتوى والعملاء والتكاملات ووكلاء الذكاء الاصطناعي من مكان واحد. يدعم واجهة عربية وإنجليزية ومساحات عمل للشركات، مع صلاحيات للفريق ومراجعات بشرية وسجل للعمليات.

يعتمد الخادم على **Node.js 24.11 أو أحدث**، ويستخدم **SQLite** لحفظ البيانات و**Ajv** للتحقق من بنية مخرجات الوكلاء. الواجهة مبنية باستخدام HTML وCSS وJavaScript.

## التشغيل المحلي

من مجلد المشروع، نفّذ:

```sh
npm ci
npm start
```

ثم افتح [التطبيق المحلي](http://127.0.0.1:3000/).

- عند التشغيل الأول، أنشئ حساب المالك بكلمة مرور من 12 حرفًا على الأقل. لا توجد بيانات دخول افتراضية.
- لا تحتاج الوظائف الأساسية إلى مفاتيح خدمات خارجية. تشغيل الذكاء الاصطناعي أو إرسال الرسائل أو النشر يتطلب إعداد التكامل المعني.
- للإعدادات الاختيارية، انسخ `.env.example` إلى `.env` إذا لم يكن الملف موجودًا، ثم أدخل القيم المناسبة. لا ترفع المفاتيح أو كلمات المرور إلى Git.

## الوظائف المتاحة

| المجال | الوظائف |

| العملاء والمبيعات | إدارة الفرص والمحادثات والمسؤولين ومسودات المتابعة |

| مساحات العمل | اختيار الشركة النشطة، إعداد مساحة العمل، إدارة الأعضاء والدعوات ومركز التحكم |
| الحسابات | التسجيل، إعدادات الحساب، التحقق من البريد الإلكتروني واستعادة كلمة المرور |

## الحسابات ومساحات العمل

حساب المستخدم يمثل هويته، وعضويته في مساحة العمل تحدد وصوله ودوره داخل الشركة. إنشاء حساب ذاتي جديد لا يمنحه الوصول تلقائيًا إلى شركات أخرى.

بعد التسجيل، يلزم التحقق من البريد الإلكتروني قبل إنشاء مساحة عمل ذاتيًا، وفق سياسة المنصة وحدودها. يمكن أيضًا الانضمام عبر دعوة. إرسال روابط التحقق والاستعادة والدعوات يتطلب إعداد بريد المنصة.

| الدور | أمثلة للصلاحيات |
|---|---|
| مشغل | إعداد المسودات وإدارة العملاء والمتابعات ضمن الصلاحيات المتاحة |
| مراجع | مراجعة المحتوى وتسجيل أدلة الامتثال |
| مالك | اعتماد المحتوى وإدارة الفريق وإعدادات مساحة العمل والوكلاء |

تُطبّق الصلاحيات على الخادم. فحص الامتثال الآلي مساعد للمراجع، ولا يحل محل المراجعة البشرية المطلوبة لاعتماد المحتوى.

راجع [التسجيل الذاتي](docs/SELF_SERVICE_SIGNUP.md)، و[إنشاء مساحة عمل](docs/WORKSPACE_CREATION.md)، و[أمان بيانات الشركات](docs/TENANT_SECURITY_MODEL.md).

## أوامر التطوير والتحقق

| الأمر | الاستخدام |
|---|---|
| `npm start` | تشغيل التطبيق عبر `app.cjs` |
| `npm run build` | فحص صياغة نقاط الدخول الأساسية؛ لا يُنتج حزمة واجهة |
| `npm test` | تشغيل اختبارات Node.js |
| `npm run test:ui` | تشغيل فحوص الواجهة باستخدام Playwright |
| `npm run ui:screenshots` | توليد لقطات للواجهة |
| `npm run agents:extract` | إعادة استخراج ملفات برومبتات الوكلاء |

تتطلب فحوص المتصفح تثبيت متصفح Playwright المناسب. نجاح فحص البناء وحده لا يثبت عمل تسجيل الدخول أو التكاملات الخارجية.

## تحديث النسخة المحلية

احفظ عملك المحلي أولًا، ثم اسحب تحديثات الفرع الذي تعمل عليه. إذا تغيّرت التبعيات، نفّذ `npm ci` مجددًا. أوقف عملية السيرفر القديمة ثم شغّل `npm start`، وحدّث المتصفح باستخدام **Ctrl + F5**.

إذا ظهرت الصفحة دون تنسيق كامل، أو أضاف نموذج الدخول الحقول إلى عنوان الصفحة، افحص تحميل ملفات JavaScript. تشغيل سيرفر قديم مع ملفات واجهة جديدة قد يؤدي إلى أخطاء `404` وتعطل النموذج؛ إعادة تشغيل السيرفر مطلوبة بعد تحديث كود الخادم.

## البيانات والنسخ الاحتياطي

المسار الافتراضي لقاعدة البيانات هو `data/hypercool.sqlite`. يمكن تغييره عبر `DATA_DIR`. المحتوى وسجل العمليات محفوظان في جداول SQL، مع ترحيل البيانات القديمة حسب [دليل ترحيل المحتوى](docs/CONTENT_MIGRATION.md) و[دليل ترحيل سجل العمليات](docs/AUDIT_MIGRATION.md).

لإنشاء نسخة احتياطية من مجلد البيانات الافتراضي:

```sh
npm run backup
```

عند استخدام مسار مخصص، مرّره صراحة:

```sh
npm run backup -- /path/to/data /path/to/backups
```

للاستعادة، أوقف التطبيق أولًا، ثم حدد ملف النسخة ومجلد البيانات:

```sh
npm run restore -- /path/to/backup.sqlite /path/to/data
```

## الاستضافة

استخدم `app.cjs` كنقطة دخول، واضبط `PUBLIC_ORIGIN` على أصل HTTPS الخاص بالتطبيق، واحتفظ بقاعدة البيانات في مجلد دائم خارج مجلدات النشر المؤقتة. شغّل نسخة تطبيق واحدة مع قاعدة SQLite الحالية، وتحقق من استمرار المجدول وبقاء البيانات بعد إعادة النشر.

راجع [دليل الاستضافة على Hostinger](docs/hostinger-deployment.md) و[ملف الإعدادات النموذجي](.env.example) قبل النشر.
