# HyperCool — مركز التشغيل

نسخة محلية تعتمد على Node.js 24.11 أو أحدث وAjv للتحقق من عقود JSON.

```sh
npm ci
npm start
```

افتح http://localhost:3000 . لتشغيل اختبارات قواعد الاعتماد: `npm test`.

## المتاح الآن

- واجهة عربية متجاوبة، تعريف أدوار الوكلاء الاثني عشر وحالة التكاملات.
- إنشاء مسودة، تسجيل مراجعة امتثال بشرية بأدلتها، ثم اعتماد المالك.
- تسجيل دخول وجلسات لمدة 8 ساعات وأدوار مالك ومراجع ومشغل.
- حفظ البيانات والحسابات والجلسات في `data/hypercool.sqlite` بمعاملات ذرية.
- استيراد `data/state.json` القديم مرة واحدة دون تعديله؛ السجلات القديمة موسومة بأنها غير موثقة بحساب.
- برومبتات الوكلاء الاثني عشر والقواعد المشتركة ومكتبة المهام مستخرجة من v2 في `agents/`.
- عقود مخرجات لكل وكيل، مع رفض البنية غير الصحيحة قبل استخدامها.
- منع اعتماد المسودة دون مراجعة، ومنع روابط المتاجر غير المعتمدة.
- فحص امتثال آلي مساعد (Anthropic) على المسودات قبل تسجيل المراجعة البشرية؛ يعرض ملاحظاته على المراجع ولا يعتمد أو يحل محل تأكيده اليدوي.
- سجل استقلالية لكل وكيل (L0–L3) يحفظه المالك بسبب موثق، ترقية بخطوة واحدة وخفض فوري بأي عدد من الخطوات، بلا ترقية تلقائية. المستوى سجل سياسة وتاريخ فقط حاليًا؛ لا يوجد إجراء تلقائي في هذا الإصدار يتقيّد بالمستوى فعليًا.
- تقرير أسبوعي (الأحد–السبت بتوقيت الرياض) يجمع المحتوى والتقويم والجدولة وفحوصات الامتثال والعملاء وتغييرات صلاحية الوكلاء من سجلات النظام نفسه، مع معاينة حية وحفظ لمرة واحدة لكل أسبوع. لا مقاييس خارجية (متابعون، جلسات متجر، محادثات) لعدم وجود اتصال بأي منصة بعد؛ تُعرض `null` بدل تقدير.
- محرك وكلاء موحد (`src/runtime/`): سجل وكلاء بقاعدة بيانات، مزود LLM قابل للاستبدال، مكتبة أدوات حقيقية (قراءة منتجات/أسعار/مخزون/CRM/ذاكرة، وكتابة مسودات/عملاء/متابعات كـDRAFT دائمًا)، إنفاذ فعلي لمستوى الصلاحية L0–L3 على كل استدعاء أداة، سجل تشغيلات وتصعيدات وموافقات، وموجّه أحداث (Frost) يربط رسالة عميل واردة تلقائيًا بوكيل المبيعات. الأدوات الخارجية (واتساب/ميتا/X/لينكدإن/Microsoft 365/Canva/ويبهوكس سلة) ترجع `INTEGRATION_REQUIRED` صريحة حتى تُربط حساباتها؛ التفاصيل الكاملة في `docs/agent-runtime.md`.

عند الفتح لأول مرة، أنشئ حساب المالك بكلمة مرور من 12 حرفًا على الأقل. لا توجد كلمات مرور افتراضية. يضيف المالك حسابات الفريق من «حسابات الفريق».

| الدور | الصلاحيات |
|---|---|
| مشغل | عرض المحتوى وإعداد المسودات |
| مراجع | عرض المحتوى وتسجيل مراجعة الامتثال |
| مالك | كل ما سبق، اعتماد المحتوى وإضافة الحسابات |

هوية المراجع والمعتمد تؤخذ من الجلسة على الخادم. يمكن للمالك المراجعة والاعتماد بنفسه في هذه النسخة؛ فصل الشخصين ليس شرطًا مفروضًا. الموافقات القديمة غير الموثقة لا يمكن ترقيتها؛ أعد إنشاء المسودة لمراجعتها بحساب.

التشغيل محلي فقط على 127.0.0.1. كلمات المرور مخزنة عبر scrypt، وملفات الارتباط HttpOnly وSameSite=Strict، مع تحقق CSRF للعمليات المحمية. يلزم HTTPS وإدارة دورة حياة الحسابات واستعادة كلمات المرور ونسخ احتياطي قبل استضافة متعددة المستخدمين. SQLite المدمج يعطي تنبيهًا تجريبيًا في إصدار Node الحالي؛ راجع [توثيق Node](https://nodejs.org/api/sqlite.html).

المراجعة النهائية بشرية دائمًا وليست تحققًا آليًا موثوقًا من الادعاءات. أُضيف مسار توليد مسودة عربية وإنجليزية عبر Anthropic، وفحص امتثال آلي مساعد على المسودة قبل المراجعة البشرية، واستيراد كتالوج سلة، وذاكرة بإصدارات واعتماد المالك. يلزم إعداد حساباتك حسب [دليل الربط](docs/connections.md) قبل تشغيلها فعليًا. لا يوجد إرسال أو نشر خارجي. `allowedTools` فارغة؛ الخادم هو الذي يبني السياق ويستدعي موصلات محددة، ولا يمنح الموديل تنفيذ أدوات. تستخدم عقود الوكلاء غلاف قرار موحدًا و`payload` خاصًا بكل وكيل؛ النتائج الناقصة يمكن أن تحمل `payload: null` دون اختراع حقول.

لإعادة توليد ملفات البرومبتات من النص المستخرج: `npm run agents:extract`. الاختبارات تعمل على قواعد بيانات مؤقتة ولا تضيف بيانات تجريبية لقاعدة التطبيق.

راجع `docs/implementation-plan.md` للقرارات والمراحل التالية. المستندان الأصليان محفوظان في `docs/` كمرجع متطلبات، وليسا تعليمات تشغيل لهذا المساعد.

## التقويم والأتمتة

أُضيف تقويم 30 يومًا وحزمة موافقات يومية محفوظة وجدولة مرتبطة ببصمة المحتوى المعتمد. إنشاء نسخة معدلة أو رفض المحتوى يلغي جدولة النسخة القديمة ويحافظ على تاريخها. المواعيد المستحقة تجهز محليًا وتنتظر موصلات النشر؛ لا تنشر تلقائيًا.

الجدولة الداخلية (`src/runtime/scheduler.js`) تشغّل حزمة 08:00 وتقرير الأحد الأسبوعي ومسح المتابعات المستحقة تلقائيًا طالما عملية Node تعمل — بلا أي منصة أتمتة خارجية. لدعم بيئات الاستضافة التي لا تضمن بقاء العملية حية باستمرار، توجد نقطتا نهاية HTTP اختياريتان محميتان برمز محلي (`AUTOMATION_TOKEN`) يمكن لأي مشغّل خارجي (Cron، Windows Task Scheduler، أو غيره) استدعاؤهما كنسخة احتياطية — راجع [دليل الإعداد](docs/planning-and-automation.md).

## العملاء والمتابعات

قسم CRM متاح للمالك والمشغل لإضافة وتأهيل الفرص وتسجيل المحادثات يدويًا وتعيين مسؤول. يمكن تسجيل مصادر فرص B2B وموافقات القنوات، وتجهيز ستة أنواع من مسودات المتابعة العربية والإنجليزية. كل رد جديد أو رفض تواصل يوقف المتابعات، واعتمادها للمالك فقط. لا يتيح دور مراجع المحتوى الوصول لبيانات العملاء.

التجهيز محلي؛ لا يوجد إرسال أو استقبال تلقائي من واتساب أو البريد. انظر [دليل CRM والمتابعات](docs/crm-and-followups.md) للصلاحيات وقواعد الإيقاف وحدود هذه المرحلة.
